# stream-edit-mining

Исследовательский набор инструментов: как из записи многочасового IRL-стрима
автоматически получить нарезку уровня живого монтажёра — и как для этого
вообще собрать обучающие данные.

Репозиторий покрывает весь путь: от сырых кусков трансляции и проектов
Adobe Premiere до датасета «слово — пауза» с мультимодальными признаками,
двух обученных моделей и обратного экспорта нарезки в Premiere.

## Задача

Уличный стрим идёт 2–4,5 часа. Монтажёр делает из него выпуск примерно на
час: 400–600 кусков с медианой 4–9 секунд, постоянно подчищая паузы внутри
живых сцен. Нужно воспроизвести его решения при условиях:

- на входе **только видео стрима**, длительность выпуска не подсказывается;
- на выходе **готовая нарезка**, а не разметка зон;
- совпадение нельзя «покупать» укорачиванием выпуска;
- данных мало: **7 пар** «стрим + монтажный лист», одна отложена как честный тест.

## Как устроено

```
куски VOD с Twitch ──► stitch/glue.py ──► full_video.mp4 ──┐
проект Premiere (.prproj) ──► stitch/remap.py ──► EDL ─────┤
опубликованный выпуск ──► edl_recovery/ ──► EDL ───────────┤
                                                           ▼
                     dataset/  расшифровка (GigaAM), лента «слово — пауза»,
                               метки из EDL, признаки: CLIP, CLAP, WavLM,
                               просодия, неожиданность речи, движение в кадре
                                                           │
                       ┌───────────────────────────────────┴──────────┐
                       ▼                                              ▼
            window_model/  окна 5–30 с,                  block_model/  блоки-реплики,
            ~2600 признаков, CatBoost                    1159 признаков, типы реплик
                       │                                 от LLM, CatBoost
                       └──────────────► EDL ◄────────────────┘
                                         │
                         render.py (ffmpeg)  ·  export_prproj.py (Premiere)
```

### `stitch/` — склейка трансляции и перенос монтажного листа

Загрузчик режет один эфир на несколько mp4, иногда с перехлёстом в пару
секунд, а проект Premiere ссылается на каждый кусок отдельно. `glue.py`
находит порядок и перехлёсты по взаимной корреляции звука (с обязательным
подтверждением на пяти независимых окнах), сажает резы на ключевые кадры
и склеивает **без перекодирования**. `remap.py` читает `.prproj` (gzip-XML)
и переводит отрезки на склеенный файл по **измеренным**, а не вычисленным
смещениям. `verify.py` проверяет синхронность звука и картинки на каждом шве
с контрольным замером вдали от швов. Подробности и разбор ложного перехлёста —
в [`stitch/README.md`](stitch/README.md).

### `edl_recovery/` — монтажный лист из опубликованного выпуска

Когда проекта нет, а есть только готовое видео на YouTube: по аудио-отпечатку
(огибающая спектрального потока, затем восьмиполосный признак) ищется, какие
куски стрима попали в выпуск. Глобальный поиск начала фрагмента, ведение,
пока сдвиг держится, двоичный поиск точки склейки, затем независимая
проверка по кадрам. `find_source.py` определяет, из какого стрима смонтирован
ролик, `selftest.py` проверяет метод на синтетическом монтаже с известным ответом.

### `dataset/` — от видео к обучающей выборке

Расшифровка через GigaAM v3, лента элементов «слово — пауза», которая строится
**только по звуку** (иначе границы элементов выдают ответ), метки из монтажного
листа и признаки: кадры 2 к/с и движение, CLIP-теги и визуальный застой, CLAP-теги
звука, изменчивость голоса по WavLM, высота голоса, неожиданность речи под
языковой моделью. `verify_dataset.py` перед обучением ловит утечку меток в тест,
дыры в ленте, расхождение с монтажным листом и общий материал между эфирами.

### `window_model/` — первый заход

Решение принимается по окнам 5/10/20/30 с, признаки собираются блоками
с кэшированием (`windows.py`), CatBoost обучается с проверкой по одному
отложенному эфиру. Сборка выбирает длину выпуска сама и сглаживает решения.
Отчёт: [`docs/window-model.md`](docs/window-model.md).

### `block_model/` — второй и третий заходы

Единица решения — реплика: пауза от 0,8 с разрывает реплику и становится
отдельным блоком, поэтому её можно вырезать поштучно, как это делает монтажёр
(потолок такой разбивки 0,93 против 0,827 у сетки 10 с). Языковая модель через
OpenRouter размечает типы реплик, CatBoost решает, что оставить, а `assemble.py`
собирает нарезку в манере монтажёра: чистит паузы по оценке модели, дробит
длинные куски и притягивает резы к тишине. `export_prproj.py` собирает проект
Premiere с готовыми резами на основе настоящего проекта монтажёра.
Отчёт: [`docs/block-model.md`](docs/block-model.md).

## Результаты

Честный тест — эфир, который не использовался ни при обучении, ни при подборе
настроек. Точность — доля нашего выпуска, совпавшая с выпуском монтажёра.

| | точность | полнота | случайно | выпуск |
|---|---|---|---|---|
| оконная модель | 0,538 | 0,492 | 0,393 | 62 мин (у монтажёра 68) |
| блочная модель | **0,542** | **0,523** | 0,393 | 65,4 мин, 447 кусков (у монтажёра 405) |

- Склейка: на всех семи эфирах сумма отрезков сошлась с таймлайном проекта
  до 0,0 мс, покадровая сверка дала разницу 0,00, рассинхрон на швах — в
  пределах ±20 мс.
- Кросс-проверка по шести эфирам: блочная модель 0,623, оконная 0,612.
- Лучшая внешняя LLM в роли монтажёра — 0,449 против 0,573 у обучаемой модели
  на том же эфире (случайно 0,303).
- Целевые 60–70 % совпадения не достигнуты. При шести обучающих эфирах надёжно
  различим только эффект больше 0,06 (стандартная ошибка прироста ±0,029),
  поэтому каждая находка проверялась вложенно.

Отдельный урок: инструкция для языковой модели — тоже обучение на данных.
Правила, выведенные из разбора обучающих эфиров, давали +0,07 на них же и
ничего не давали на отложенном эфире.

## Установка

Нужны Python 3.9+, `ffmpeg` и `ffprobe`. Для признаков на основе нейросетей —
GPU с CUDA.

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env    # пути и ключ API, затем: set -a; source .env; set +a
```

Скрипты запускаются из корня репозитория. Пути к данным задаются переменными
окружения:

| Переменная | Что лежит |
|---|---|
| `SEM_STREAMS` | эфиры по слотам: `<N>/streams/full_video.mp4`, `<N>/narezki/timecodes.json` |
| `SEM_SOURCES` | исходные видео: полные стримы и опубликованные выпуски |
| `SEM_DATASET` | ленты элементов, `train.jsonl`, звук |
| `SEM_WORK` | рабочий каталог оконной модели: `data/`, `cache/`, `vid/`, `aud/` |
| `SEM_BLOCKS` | данные блочной модели |
| `SEM_TMP` | промежуточные файлы |
| `SEM_ASR_HOST`, `SEM_ASR_DIR` | сервер с GigaAM для расшифровки (по ssh) |
| `OPENROUTER_API_KEY` | ключ для языковых моделей |

## Пример

```bash
# 1. склеить куски эфира, проверить швы и перенести монтажный лист из Premiere
#    (в слоте: streams/*.mp4 и narezki/*.prproj)
python3 stitch/process_slot.py $SEM_STREAMS/3

# 2. лента элементов и признаки
python3 dataset/pipeline.py 3
python3 dataset/frames.py 3
python3 dataset/clip_feat.py 3

# 3. блочная модель: подготовка, обучение, сборка нарезки
python3 block_model/prep.py --slot 3
python3 block_model/feats_server.py --slot 3
python3 block_model/train_predict.py --held 2
python3 block_model/assemble.py --slot 2 --density 7.06 --maxseg 80
```

## Стек

Python, NumPy, CatBoost, scikit-learn, PyTorch, Hugging Face Transformers
(CLIP ViT-L/14, CLAP, WavLM, multilingual-e5, Qwen2.5-7B, Qwen3-VL-8B),
GigaAM v3, ffmpeg, OpenRouter API.

## Структура

```
stitch/            склейка кусков трансляции, перенос монтажного листа из .prproj
edl_recovery/      восстановление монтажного листа по опубликованному выпуску
dataset/           расшифровка, лента элементов, метки, признаки, проверки выборки
  experiments/     видео-языковые модели как судьи по кадру
window_model/      оконная модель: признаки, обучение, сборка, рендер
  diagnostics/     разбор работы монтажёра и ошибок модели
  experiments/     проверенные и отвергнутые идеи
block_model/       блочная модель: реплики, признаки, обучение, сборка, экспорт
  llm/             монтаж и разметка языковыми моделями
  prompts/         правила монтажа для подсказки
  experiments/     проверенные и отвергнутые идеи
docs/              отчёты по заходам со всеми замерами
```

Видео, проекты Premiere, расшифровки и разметка в репозиторий не входят.
