# Блочная модель: реплики, правила и языковые модели

Второй и третий заходы. Первый (оконная модель, `docs/window-model.md`)
упирался в 0,538 на честном тесте и собирал выпуск монолитами по
несколько минут. Здесь единица решения — реплика, а сборка повторяет
манеру монтажёра.

## Итог на честном тесте (слот 2)

Конфигурация зафиксирована до вскрытия слота, по нему ничего не подбиралось.

| | наша нарезка | монтажёр |
|---|---|---|
| кусков | 447 | 405 |
| медиана куска | 5,6 с | 6,2 с |
| самый длинный | 74 с | 74 с |
| длина выпуска | 65,4 мин | 67,7 мин |
| **точность** | **0,542** | — |
| полнота | 0,523 | — |
| случайно | 0,393 | — |

По точности — небольшой прирост к первому заходу (0,538). Главное
изменилась **форма**: раньше выпуск состоял из 99 кусков, теперь это
плотная нарезка, по структуре неотличимая от работы монтажёра.
Целевые 60–70 % не достигнуты.

    python3 block_model/train_predict.py --held 2       # обучение и оценки
    python3 block_model/assemble.py --slot 2 --src pb --density 7.06 --maxseg 80 \
        --scores $SEM_BLOCKS/final3_s2.npy               # сборка нарезки

## Контрольные опыты

1. **Текст исчерпан.** Языковая модель, собиравшая выпуск слота 7 вслепую
   по размеченным эфирам, дала 0,459 и 0,494. Наша модель при той же
   длине — 0,510 и 0,526.
2. **Семантика кадра не добавляет.** Описания 6900 кадров дают +0,002.
3. **Дело не в переносе между эфирами.** Обучение на трёх четвертях того же
   стрима — 0,410, на пяти чужих — 0,536.

## Двухступенчатая схема (третий заход)

Гипотеза: первая модель крупными зонами 20–60 с говорит, что НЕ брать,
вторая чистит паузы внутри. Проверено во всех сочетаниях — точности
не даёт.

    потолок схемы (идеальные зоны + наша чистка)   0,782
    потолок (наши зоны + идеальная чистка)         0,723
    база                                           0,620
    нужен судья зон с AUC 0,85, чтобы дать +0,05

    судья зон: наша оценка        AUC 0,768
               LLM «не брать»         0,669
               LLM «оставить»         0,684
               зонная модель          0,788 (против 0,787 у агрегата)

Вложенная проверка лучшей комбинации: **−0,004 ± 0,007**. Инструменты:
`experiments/twostage.py`, `zonecurve.py`, `zonemodel.py`, `stage2.py`.

## Тупики — не повторять

- Свод правил в подсказке хуже черновых: 0,355 против 0,445.
- Карта стрима в контексте: 0,423 против 0,445.
- Выбор окон одним запросом: 0,401.
- Весь стрим одним запросом: 0,362; без `reasoning: {"effort": "high"}`
  модель вырождается в «1-1, 2-2, 3-3…».
- Обучение на парах: парная точность 0,719, глобально 0,469.
- Вето языковой модели поверх бустинга: любой вес вредит.
- Зоны по кадрам: отбор только по типу зоны 0,356.

## Грабли

- **Паузы короче LONG склеиваются с речью** и не режутся поштучно — из-за
  этого выпуск собирался монолитами. Отсюда GAP = LONG = 0,8 с.
- **Правило «начать в первые 90 секунд» слишком слабое**: модель начинала
  со 112 секунд тишины. Начинать надо с речи.
- Файлы данных нельзя перегенерировать, пока по ним идёт разметка:
  нумерация блоков поедет, и все ссылки на блоки станут неверными.

## Стоимость

Разметка стрима языковой моделью — $0,007 и 35 секунд. Описание кадров
одного стрима на своей видеокарте — 7 минут. За оба захода на API
израсходовано $2,4.
